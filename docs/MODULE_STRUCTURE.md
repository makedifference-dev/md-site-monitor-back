# Структура модулей API

## Обзор

API организован по принципу бизнес-модулей, где каждый модуль содержит всю логику, связанную с определенной областью функциональности.

## Архитектура модулей

```
src/
├── app.ts                    # Точка входа приложения
├── modules/                  # Бизнес-модули
│   ├── core/                 # Основные утилиты и типы
│   ├── auth/                 # Аутентификация и авторизация
│   ├── projects/             # Управление проектами
│   ├── monitoring/           # Мониторинг сайтов
│   ├── notifications/        # Email и Telegram уведомления
│   ├── telegram/             # Telegram бот
│   ├── health/               # Проверка здоровья системы
│   ├── cache/                # Кэширование данных
│   ├── database/             # Работа с базой данных
│   ├── error/                # Обработка ошибок
│   ├── docs/                 # Документация API
│   └── api-info/             # Информация об API
└── test/                     # Тесты
    ├── unit/                 # Модульные тесты
    ├── integration/          # Интеграционные тесты
    └── e2e/                  # End-to-End тесты
```

## Детальное описание модулей

### 🔧 Core Module (`src/modules/core/`)

**Назначение:** Основные утилиты, типы и middleware, используемые во всем приложении.

**Компоненты:**

- `types.ts` - Общие типы для переиспользования
- `graceful-shutdown.ts` - Graceful shutdown приложения
- `performance.middleware.ts` - Middleware для производительности

**Экспортируемые типы:**

- `PaginationInfo` - Информация о пагинации
- `HealthCheck` - Проверка здоровья системы
- `NotificationConfig` - Конфигурация уведомлений
- `TelegramBotConfig` - Конфигурация Telegram бота
- `TelegramUser` - Пользователь Telegram
- `TelegramNotification` - Уведомление Telegram
- `ApiResponse<T>` - УДАЛЕН (не использовался в коде)
- `RequestUser` - Пользователь в Express Request (перенесен в auth модуль)

### 🔐 Auth Module (`src/modules/auth/`)

**Назначение:** Аутентификация и авторизация пользователей.

**Компоненты:**

- `auth.service.ts` - Бизнес-логика аутентификации
- `auth.controller.ts` - HTTP контроллер
- `auth.middleware.ts` - Middleware для проверки JWT
- `auth.types.ts` - Типы для аутентификации (включая RequestUser)
- `auth.docs.ts` - Swagger документация
- `auth.module.ts` - Конфигурация модуля

**Функциональность:**

- Регистрация пользователей
- Вход в систему
- Обновление токенов
- Выход из системы
- Получение профиля пользователя

### 📊 Projects Module (`src/modules/projects/`)

**Компоненты:**

- `projects.service.ts` - Бизнес-логика проектов
- `projects.controller.ts` - HTTP контроллер
- `projects.types.ts` - Типы для проектов
- `projects.docs.ts` - Swagger документация
- `projects.module.ts` - Конфигурация модуля

**Функциональность:**

- Ограничение: 3 активных проекта на пользователя

## Принципы организации

### 1. Инкапсуляция

Каждый модуль содержит всю логику, связанную с его функциональностью:

- Сервисы (бизнес-логика)
- Контроллеры (HTTP обработчики)
- Middleware (если специфичны для модуля)
- Типы и интерфейсы
- Документация

### 2. Переиспользование

Общие компоненты вынесены в соответствующие модули:

- `core/` - общие утилиты и типы
- `docs/` - документация
- `database/` - работа с БД
- `cache/` - кэширование

### 3. Зависимости

Модули могут зависеть друг от друга через dependency injection:

- `monitoring` → `notifications` (уведомления о падении)
- `monitoring` → `telegram` (Telegram уведомления)
- Все модули → `error` (обработка ошибок)
- Все модули → `cache` (кэширование)

### 4. Конфигурация

Каждый модуль имеет свой конфигурационный файл (`*.module.ts`), который:

- Регистрирует роуты
- Настраивает middleware
- Управляет зависимостями
